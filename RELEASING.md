# Сборка, выпуск и обновления SafeNet

Коротко: код живёт в ветках, а пользователям уходит только то, что помечено тегом
версии `vX.Y.Z` в `main`. Тег запускает сборку на GitHub, и приложения обновляются
сами из этого выпуска.

## 1. Сборка

Всё собирается скриптами, без Xcode.

| Команда | Что делает |
|---|---|
| `scripts/build.sh` | компилирует код в `.build/SafeNetApp` |
| `scripts/test.sh` | собирает и запускает все тесты |
| `scripts/build-app.sh` | собирает `dist/SafeNet.app` и `dist/SafeNet.zip`: универсальная сборка (Intel + Apple Silicon), подпись без сертификата Apple |
| `scripts/build-app.sh --dev` | то же, но **без обновлений**: метка DEV, версия «x.y.z (dev)», релиз такую сборку не заменит |
| `scripts/fetch-singbox.sh` | скачивает закреплённую версию sing-box в `vendor/` (для тестов VPN; в приложение не входит) |

Версия берётся из файла `VERSION` (например, `1.0.8`). Скрипт записывает её в
`Info.plist` и вычисляет номер сборки: 1.0.8 → 10008.

Тестовую сборку запускают прямо из папки проекта, предварительно выйдя из
установленного SafeNet (две копии одновременно не запускаются):

```bash
scripts/build-app.sh --dev
open dist/SafeNet.app
```

## 2. Как выходит релиз

```
main ──(VERSION=x.y.z, коммит)──► scripts/release.sh publish x.y.z
                                         │ пушит тег vx.y.z
                                         ▼
                 GitHub Actions (.github/workflows/release.yml)
                  тесты → сборка → подпись → релиз на GitHub:
                  SafeNet-x.y.z.zip · update.json · update.json.sig
```

- **Подпись.** Закрытый ключ хранится только в секрете GitHub `SAFENET_RELEASE_KEY`
  и локально в `~/.config/safenet/update-signing.key`. Открытый ключ вшит в
  `Info.plist` каждой копии. Если закрытый ключ потерять, установленные копии больше
  не примут ни одного обновления. Держите резервную копию ключа.
- **`update.json`** описывает выпуск: версию, ссылку на zip, SHA-256 и размер.
  **`update.json.sig`** — подпись этого файла ключом Ed25519.

## 3. Как приложение обновляется

1. Раз в сутки (или по «Проверить сейчас») приложение скачивает
   `…/releases/latest/download/update.json` и его подпись.
2. Проверяет, что подпись сделана вашим ключом. Без неё дальше ничего не скачивается.
3. Если версия новее своей, скачивает zip и сверяет размер, SHA-256 и подпись кода
   (`codesign`).
4. Ставит обновление только когда безопасно: ничего не заморожено, не закрыто и не
   на паузе. Иначе ждёт.
5. Приложение закрывается, помощник `--install-update` подменяет `SafeNet.app` и
   запускает новую версию. Если она не подтвердила запуск за 45 секунд, помощник
   откатывает обновление.

Режим задаётся в `config.yaml`: `updates: auto | notify | off`.

> **Любой тег `vX.Y.Z`, отправленный на GitHub, через несколько минут становится
> обновлением у всех пользователей.** Теги ставятся только на проверенный `main`.

## 4. Ветки

- **`main`** — только то, что готово к выпуску. Напрямую не коммитим, только через PR.
- **`dev`** — общая тестовая ветка: сюда сливается то, что проверяется на
  `--dev`-сборке.
- **`feature/…`, `fix/…`, `design/…`** — по ветке на задачу. Отводятся от `dev`
  (срочные исправления — от `main`).

## 5. Цикл задачи

1. Ветка под задачу:

   ```bash
   git switch dev && git pull && git switch -c feature/что-то
   ```

2. Код и проверка: `scripts/test.sh`, затем `scripts/build-app.sh --dev` и
   `open dist/SafeNet.app`.
3. Слить ветку задачи в `dev` и проверить там вместе с остальным.
4. Когда `dev` готов к выпуску — PR из `dev` в `main`, слить.
5. Выпуск из `main`:

   ```bash
   git switch main && git pull
   echo 1.0.8 > VERSION && git commit -am "SafeNet 1.0.8" && git push
   scripts/release.sh publish 1.0.8
   ```

6. Через несколько минут проверить, что релиз появился на GitHub и что
   `…/releases/latest/download/update.json` отдаёт новую версию.

**Срочное исправление:** ветка `fix/…` от `main` → PR в `main` → выпуск, затем
слить `main` обратно в `dev`, чтобы исправление было и там.

## 6. Правила

- Номер в `VERSION` всегда растёт. Совпадающая или меньшая версия до пользователей
  не дойдёт.
- Каждый выпуск — один коммит «SafeNet x.y.z» и тег `vx.y.z` на нём.
- Тестовые сборки — только с `--dev`.
- Над проектом работает несколько человек: перед выпуском всегда `git pull` в
  `main`, чтобы не выпустить версию поверх чужой.
- Слитые ветки удаляйте: `git branch -d <ветка>` и
  `git push origin --delete <ветка>`.
