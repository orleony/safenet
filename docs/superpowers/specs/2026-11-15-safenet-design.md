# SafeNet — kill switch для приложений на macOS (дизайн)

Рабочее название: **SafeNet** (по имени папки; название и логотип оригинала не используем).
Дата: 2026-11-15. Статус: на согласовании.

## Зачем

Заказчик пользуется приложением сам, для себя. Ему нужен «kill switch для приложений», как у Kordon (github.com/ef1m03/kordon): если VPN отвалился или внешний IP/страна не из разрешённых, выбранные программы (Claude, Cursor, Telegram и т.д.) замораживаются, а если правильный адрес так и не вернулся за заданное время, закрываются. Остальной интернет не трогается.

Дизайн оригинала не понравился. Поэтому делаем своё приложение с тем же набором возможностей, но с настраиваемым внешним видом.

У оригинала с версии 1.3.0 закрытая лицензия, исходников в репозитории нет. Пишем с нуля по публичному описанию функций, без кода и без названия/логотипа оригинала.

## Цели

- Нативное приложение в строке меню, macOS 13 Ventura и новее (проверяем на 13.7.8 Intel, должно работать и на новейшей), Intel и Apple Silicon (универсальный бинарник).
- Заморозка выбранных приложений за доли секунды при потере VPN, смене сети или IP/страны вне разрешённых.
- **Заданное время заморозки** (глобально и для каждого приложения). Когда время вышло, а правильный IP не вернулся, **приложение закрывается** (переключатель в настройках: закрыть / держать замороженным / разморозить, по умолчанию «закрыть»).
- Настраиваемый дизайн: тема «светлая / тёмная / как в системе» (по умолчанию как в системе, меняется сама), выбор акцентного цвета (по умолчанию **синий**), плотность, шрифт (системный/моно), что показывать в строке меню (IP, страна или значок).
- Работа без прав администратора, без платных сервисов и API.

## Не цели и антицели

- Не делаем: Windows и Linux, Telegram-пульт, автообновление и «Что нового», браузерное расширение (WebRTC), готовую подписку/облако.
- Не отправляем ничего в сеть, кроме проверок IP и маршрута (см. «Приватность»). Нет телеметрии.
- Антицель: приложение, которое выглядит красиво, но при сбое молча пускает программы с неправильного адреса. Безопасное поведение при любой неопределённости важнее удобства.
- Не копируем код, название, логотип и скриншоты оригинала.

## Объём (что делает приложение)

1. **Ядро.** Определяет внешний IP и страну по нескольким сервисам (должно совпасть не менее N, по умолчанию 2). Реагирует на смены сети (системные события) и опрашивает по таймеру (по умолчанию раз в 5 с). Состояния: ок / заморожено / закрыто / пауза.
2. **Заморозка.** `SIGSTOP`/`SIGCONT` по процессам, сопоставленным с выбранными приложениями (включая дочерние процессы и хелперы). Закрытие: сначала вежливо (`terminate`), по таймауту принудительно.
3. **Приложения.** Готовые наборы (Claude, ChatGPT, Cursor, Telegram и т.п.), «браузеры для ИИ», свои приложения (сопоставление по имени, части пути, части командной строки) и правила для каждого (разрешённые страны/IP, своё время заморозки).
4. **Разрешено.** IP, подсети (CIDR), страны, общие для приложений без своих правил.
5. **Доверенные сети.** Дом/офис без VPN, остальные сети под защитой. «Доверять этой сети» из панели; сеть опознаётся по идентификатору шлюза.
6. **Проверки.** IPv6 мимо VPN, утечка DNS (режимы warn / block / off), кнопка глубокой проверки утечек, **маршрут до ИИ-сервисов**: запрос `/cdn-cgi/trace` у api.anthropic.com, claude.ai, chatgpt.com, api.openai.com, www.perplexity.ai (раз в ~2 мин и после смены сети, только если есть защищённые программы). Если сервис видит неразрешённый адрес, приложение встаёт на паузу. Работает с VPN в режиме системного прокси.
7. **Статистика и история.** Сколько раз VPN вернулся вовремя и сколько раз закрывались приложения; история событий (смены сети и IP, заморозки, закрытия) с фильтром и очисткой.
8. **Интерфейс.** Окно из строки меню (флаг, IP, состояние, переключатели приложений, «Пауза», «Панель →») и панель с вкладками: Обзор, Приложения, Разрешено, Сети, Проверка, Статистика/Журнал, Настройки. В состоянии «заморожено» на Обзоре идёт отсчёт до закрытия и кнопки «Разрешить этот IP», «Продлить», «Закрыть сейчас».
9. **Настройки.** Все параметры переключателями и в файле `config.yaml` в `~/Library/Application Support/SafeNet/` (подхватывается без перезапуска; при ошибке уведомление и работа на старых настройках).
10. **CLI** (минимальный): `status`, `allow [ip|страна]`, `panel`, `config`.
11. Автозапуск при входе в систему, уведомления macOS.

## Утверждённые решения

- **Подход A: нативный Swift/SwiftUI**, а не Electron/Tauri/Python. Причины: нужен лёгкий постоянно работающий агент, системные события сети, родной вид.
- Иконка и окно: `MenuBarExtra` (macOS 13+); автозапуск через `SMAppService`; сборка через SwiftPM/`swiftc` без Xcode.
- Стиль: вариант **A «Тёмное стекло»**, но с темой по системе или выбором вручную; акцент по умолчанию синий; статусы всегда зелёный / оранжевый / красный независимо от акцента.
- Срок заморозки истёк → закрываем приложение (по умолчанию).
- Раздельная маршрутизация в оригинале — это проверка, а не настройка маршрутов; делаем так же.

## Решения по безопасности и архитектуре (мои, на проверку)

Закрыты вопросы ревьюера. Всё ниже решил я, не заказчик.

**Состояния и неопределённость**
- Состояния: `ок`, `заморожено`, `закрыто`, `пауза`.
- «Пауза» — только кнопка пользователя: защита выключена, приложения разморожены, виден таймер возврата защиты (по умолчанию 15 мин). Провал проверки маршрута до ИИ-сервиса — это не «пауза», а обычная заморозка с обратным отсчётом, как при неправильном IP.
- Неопределённость = заморозка. Если ответили меньше N сервисов IP, сервисы расходятся по IP или стране, либо не отвечают при активной сети, приложения замораживаются.
- **Нет сети вообще** (оффлайн) — замораживаем (как `block_when_offline` в оригинале, настраивается), но **не закрываем**: пока сети нет, ничего не утекает, а закрытие потеряло бы несохранённую работу. Таймер закрытия идёт только когда сеть есть, а адрес неправильный или не подтверждён.
- Чтобы единичный сбой одного сервиса не закрыл приложение: закрытие только после полного срока заморозки, и срок сбрасывается, как только проверка снова проходит.

**Сигнал «VPN отвалился»**
- Не только внешний IP. Монитор системных событий сети (SystemConfiguration / `NWPathMonitor`: интерфейсы `utun*`, маршрут по умолчанию, прокси) запускает мгновенную заморозку и проверку, плюс опрос IP раз в 5 с как страховка (для VPN в режиме прокси смотрим системный/PAC-прокси). Запрос IP идёт обычным маршрутом, чтобы показывал то, что видят приложения.

**Аварийная разморозка (главная гарантия)**
- Перед каждой заморозкой PID записываются на диск. При выходе, завершении системы и запуске приложение размораживает всё записанное. Лёгкий дочерний процесс-страж (тот же бинарник) размораживает приложения, если основной процесс умер (сбой, `kill -9`).
- Пока приложения заморожены, а SafeNet закрыт пользователем, они размораживаются (пользователь сам решил выйти). Сон/пробуждение: после пробуждения сразу новая проверка.

**Правила и сопоставление**
- Правила приложения **заменяют** общий список «Разрешено» для этого приложения (не дополняют). Заморозка решается для каждого приложения отдельно.
- Страна берётся из ответов тех же сервисов; чтобы IP считался подтверждённым, не менее N сервисов должны назвать один IP и одну страну.
- Список «никогда не замораживать»: сам SafeNet, `launchd`, `WindowServer`, Finder, Dock, `loginwindow`, системные процессы (пути `/System`, `/usr/libexec`) и процессы других пользователей. Правило по части командной строки действует только на процессы пользователя вне этого списка. Хелперы приложения замораживаем вместе с ним.

**Доверенные сети**
- Идентификатор: MAC шлюза (из таблицы ARP) вместе с IP шлюза и подсетью, а не одно имя сети или SSID (разрешение геолокации не нужно). Одинаковый `192.168.1.1` у разных роутеров сам по себе доверия не даёт.

**Конфигурация**
- Источник истины — файл `config.yaml`: интерфейс читает и пишет в него; ручные правки подхватываются и показываются в интерфейсе. При записи из интерфейса комментарии сохраняются по возможности (парсер Yams через SwiftPM, MIT; если без сети собрать нельзя — упрощённый встроенный разбор).

**Сборка и распространение**
- Результат — обычный `.app` (универсальный: x86_64 + arm64, `LSUIElement`, ad-hoc подпись) и отдельный консольный бинарник `safenet` (тот же код, режим CLI). CLI общается с запущенным приложением через unix-сокет в `~/Library/Application Support/SafeNet/`.
- Slice arm64 собирается кросс-компиляцией и проверяется только сборкой; поведение проверено на этом Intel Mac. Это стоит учитывать при выдаче заказчику.

**Проверяемость**
- Сетевой слой, список процессов и часы спрятаны за протоколами, чтобы тестировать логику состояний, заморозки и таймеров без настоящего VPN и без настоящих приложений. Для ручной проверки есть тестовый режим с подставным IP.

## Ограничения

- Среда сборки на этом Mac: macOS 13.7.8, Intel, Swift 5.8.1 (Command Line Tools). Значит, без Swift 5.9+ (макрос `@Observable` недоступен, использовать `ObservableObject`), SwiftUI на 13-й версии (старая форма `onChange`, нет `openSettings`, поэтому окно настроек открываем вручную).
- Права: без администратора. Замораживать можно только процессы пользователя. Для некоторых приложений может потребоваться разрешение в «Конфиденциальность и безопасность».
- Подпись: ad-hoc; запуск на другом Mac потребует разрешить в «Системных настройках» (Developer ID не используется).

## Приватность

Наружу уходят только запросы IP-сервисам и `/cdn-cgi/trace` ИИ-сервисов (только когда есть защищённые приложения), как у оригинала. Личные данные и настройки не отправляются. Обновлений и аналитики нет.

## Рассмотренные подходы

| Подход | Итог |
|---|---|
| A. Swift/SwiftUI, нативно | **Выбран.** Лёгкий, системные события, родной вид, универсальный бинарник. Минус: капризы SwiftUI на 13-й версии. |
| B. Tauri/Electron | Отклонён: тяжёлый, заморозку и сеть всё равно писать нативно. |
| C. Python + rumps | Отклонён: упаковка под Intel+ARM на 13+ болезненна, интерфейс слабый. |

## На усмотрение исполнителя

- Набор IP-сервисов и стратегия опроса, формат хранения истории и статистики.
- Как именно сопоставлять процессы и хелперы приложений; список готовых наборов.
- Точные значения плотности и размеров, имена тем, набор акцентных цветов.
- Раскладка вкладок и состав «Журнала».
